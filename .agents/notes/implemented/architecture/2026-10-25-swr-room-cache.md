# Browser-wide SWR room cache primitives

`session-controller/src/client/cache/swr-cache.ts` provides the cache core for room metadata and recent history. Keys are `hm:<tenant>:<user>:<kind>:<id>`, and segments containing `:` are rejected so one account's prefix never matches another's keys. `SwrCache.load` returns the stored value immediately and revalidates in the background; concurrent loads of one key share a single fetch, and failed fetches are not cached. `hydrate` reads the persistent store into memory on cold start. Writes and account clears are broadcast on a BroadcastChannel so sibling tabs drop stale copies. `clearAccount` removes one account's keys only. `mergeHistoryBySeq` merges a cached history window with live events, keeping one entry per `seq`, with the live entry winning, sorted ascending.

`swr-account.ts` resolves the account from `/v1/bootstrap` (organization id as tenant, user id as user, UUIDs validated). `openSwrStore` opens an IndexedDB store and falls back to memory when IndexedDB is missing or fails to open. `AccountCacheScope` clears the previous account on account change and on sign-out.

Wired: `SessionManager.refreshList` reads the cached session list on the first load (list phase still pending) and shows it before the server pull resolves. The pull then replaces it through the existing ordered merge, and a successful pull writes the server list back. The list is the room metadata source (title, cwd, preset, running state), so it covers room metadata too. The cache is scoped by the bootstrap identity through `SessionListCache`, which clears the previous account on account change or sign-out. It is created only where IndexedDB exists, so jsdom tests and browsers without IndexedDB keep the live-only list.

Not wired, deliberately: the latest history window. The history read path runs through the journal stream's reconnect baseline, and a cached window there changes which seqs count as published. That needs a live check, so it is a separate change. Timed before and after numbers are not recorded yet.

Acceptance: `packages/api/session-controller/tests/swr-account.client.spec.ts` covers identity resolution, UUID validation, the memory fallback paths, and account-change clearing. `packages/api/session-controller/tests/session-list-cache.client.spec.ts` covers cached rows shown before the pull, server replacement, write-back on success only, the live-only path, and account isolation. `packages/api/session-controller/tests/swr-cache.client.spec.ts` covers key construction and rejection, tenant and user isolation, sign-out clear scope, stale-while-revalidate, single-flight fetches, cold-start hydrate, failed fetches, cross-tab write and clear propagation, and seq merge.
