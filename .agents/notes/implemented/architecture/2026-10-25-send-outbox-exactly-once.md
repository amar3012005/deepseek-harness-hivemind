# Send outbox with exactly-once rpcId

`session-controller/src/client/sessions/send-outbox.ts` queues messages typed before the Session subscription is ready. Each message mints one `rpcId` at enqueue; a retry reuses that id, so the responder can deduplicate. A message leaves the outbox only when the responder acknowledges its id. `beginConnection` starts a connection generation: within one generation an entry is handed to the transport at most once, and after a reconnect every unacknowledged entry is resent with its original `rpcId`. Overlapping flushes return at once. Subscribers are notified on enqueue and acknowledgement, for optimistic bubbles.

Assumption: the responder deduplicates by `rpcId`. The Connection contract says the initiator mints and the responder echoes, so a resend with the same id must not create a second message. This outbox does not prove that; the server side must be checked.

Wired, narrowly: `Session.prompt` holds a top-level prompt that arrives while the subscription is `loading`, under the echo's `requestId`, and `doOpen` flushes it when the subscription opens. Sessions that are cold or already open keep the direct send, so existing first-send behavior is unchanged. The server deduplicates by `requestId`: `packages/api/session-controller/src/commands.ts:387` returns `accepted` without re-admitting when `hasPromptRequest` (lines 690–701) finds the same `rpcId` in the inbox or the durable `user/message` log. The durable echo acknowledges the held entry in `observeSubmissionEvent`. A server-rejected flush drops the entry, retires the echo, and sets `promptError`; a transport failure keeps it for the next open.

Not wired: sessions that are cold or already open still send directly, so a send lost in transit on an open session is not retried by the outbox. Widening the hold to every non-open state changes the first-send contract that existing session tests assert, so it needs a product decision.

Acceptance: `packages/api/session-controller/tests/session-outbox-wiring.client.spec.ts` covers the hold while loading, the flush on open with the echo's requestId, rejection handling, and the direct send on an open session. `packages/api/session-controller/tests/send-outbox.client.spec.ts` covers one mint per message, in-order sends, retry with the same id after a failed send, acknowledgement removing an entry permanently across reconnect, no double-send on overlapping flushes, and no resend within a connection before acknowledgement.
