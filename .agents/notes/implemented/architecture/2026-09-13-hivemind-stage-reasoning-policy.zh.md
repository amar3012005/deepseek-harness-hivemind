# Agent Note：HIVE 按持久化工作流阶段分配推理预算

状态：已实现

[English](2026-09-13-hivemind-stage-reasoning-policy.md) | 中文

## 问题

对所有 HIVE 请求强制使用同一种推理强度，要么会在直接和有界任务上浪费 token，要么会削弱复杂执行手册的质量。要求“简短思考”的提示词无法可靠控制提供商的推理 token 消耗。文本分类器会重复模型的意图判断，并带来应用专属维护。

## 决策

HIVE 运行时使用原生 `agent/request` 瀑布，不修改 Cordis 循环。它只从当前轮次的工具事件推导持久化工作流阶段：

- 首次决策和准确契约映射的后续步骤请求 `low`。
- 完成有界 HIVE 查询、连接应用执行或连接状态回执后的综合请求 `off`。
- 模型主动加载详细技能后的后续步骤请求 `high`。

在提示获准前，已注册适配器会针对准确选中的模型验证建议强度。不支持该强度（包括强制推理）的模型保留其原生默认值。用户通过原生模型或会话控件显式选择的强度仍具有最高优先级。

该策略不包含提示正则、用户标识、提供商名称、工具包名称或应用专属规则。完整请求头和工作流事件继续以仅追加方式保存并可重放。

## 验证

运行时测试覆盖首次、有界、连接搜索、连接执行和技能已加载阶段。测试还证明显式强度会被保留，不支持的强度会安全回退。聚焦的 HIVE 上下文、运行时、连接应用、预设和 Bundle 测试保持通过，运行时包也通过了针对性的 TypeScript 检查。

## 后果

模型继续负责意图、能力、技能和工具决策。HIVE 只在决策成为持久化事实后控制提供商预算。未来技能会自动继承相同行为，因为该策略识别原生技能工具，而不是任何具体技能名称。
