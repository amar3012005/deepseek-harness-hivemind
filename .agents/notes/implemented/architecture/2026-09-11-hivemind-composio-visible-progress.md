# HIVE-MIND Composio visible progress

The HIVE connected-app plugin keeps `hivemind_connected_task` as its single model-facing progressive router. Composio meta-tool calls remain implementation details of that tenant-scoped tool, while their names and completion states are recorded in the tool result so the native keyed tool view can project search, connection, schema, wait, and provider progress during replay.

An agent turn starts with one connected-app search and may continue discovery only inside the returned workflow session when a selected contract still lacks a provider-owned prerequisite. The plugin rejects identical repeated searches and cross-workflow search, while a materially refined `tool_search` merges its selected tools and exact contracts into the active workflow. A connection-required result remains authoritative: inference stops and continuation waits for verified user connection state.

The server-side Composio router session derives its identity from the authenticated HIVE user and conversation. Its session identifier is recorded as a log-only session event, restored after runner restart, and cached before any connected-account lookup. Search receipts retain selected slugs, connection status, planning guidance, and the private spill reference; provider credentials and tenant identifiers never enter model-visible arguments. The HIVE persona bounds narrated reasoning without forcing one provider-wide reasoning level onto models with different capabilities.
