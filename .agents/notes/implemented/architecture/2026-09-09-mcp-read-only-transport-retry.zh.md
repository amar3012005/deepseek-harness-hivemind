# Agent Note：MCP 传输恢复仅重试已声明的读取操作

状态：已实现

[English](2026-09-09-mcp-read-only-transport-retry.md) | 中文

## 问题

Streamable HTTP MCP 端点可能在服务仍健康时丢失协议会话，或返回短暂的 502、503、504 响应。轮换失败的客户端能够修复后续调用，但当前 Harness 工具执行仍会失败。重放所有调用可能重复一次结果未知的外部写入。

## 决策

MCP 连接监督器负责替换协议世代。发生可恢复的传输失败时，它关闭失败客户端，通过现有有界策略重连，同步服务器工具世代，并把已连接客户端交给等待中的调用方。

只有服务器为该工具声明 `annotations.readOnlyHint: true` 时，桥接才会把原始网络请求重复一次。未声明及可写工具绝不重放；其失败世代仍会轮换，以修复后续调用。重试再次失败时也会为后续工作轮换客户端，但会终止当前执行。取消、重连耗尽、禁用重连和插件销毁都会用错误结束等待中的调用。

两次网络请求属于同一次 Harness 工具执行。现有持久工具事件、结果映射、策略 waterfall 和 UI 卡片保持不变。

## 考虑过的替代方案

- **重试所有短暂传输失败**——拒绝，因为响应丢失前远程操作可能已经完成，重放可能产生重复写入。
- **按名称匹配安全工具**——拒绝，因为名称由部署决定，不能表达 MCP 操作语义。
- **让后续模型步骤处理恢复**——拒绝，因为这会把可恢复的读取中断暴露给模型，并为传输修复额外消耗一次模型请求。

## 结果

- 明确声明为只读的 MCP 工具可以容忍一次 Streamable HTTP 世代丢失，且不增加模型步骤。
- 未提供 `readOnlyHint` 的服务器采用保守行为：为后续调用修复连接，但不自动重放。
- 此重试不会增加工具 schema、提示词、会话事件或模式专用行为。

## 验证

- `packages/mcp/mcp-client/tests/reconnect.spec.ts` 覆盖只读重试成功、未声明工具不重试、世代替换及既有重连生命周期行为。
- `packages/mcp/mcp-client/tests/mcp-client.spec.ts` 保持原生结果与附件投影。
