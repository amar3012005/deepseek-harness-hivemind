# Agent Note：HIVE 能力目录按需请求

状态：已实现

[English](2026-09-12-hivemind-on-demand-capability-catalog.md) | 中文

## 问题

原生技能插件会在每个首个模型步骤中提供精简 HIVE 目录。即使是问候或可由最近对话直接回答的问题，也要承担目录注入成本，并容易触发不必要的规划。服务器端关键词分类器虽然减少了部分调用，却会让能力可见性依赖猜测的意图，并要求为未来每个技能持续维护。

## 决策

HIVE 的初始模型步骤只包含系统契约、有界的已完成用户请求与最终回答，以及当前未完成的工作流状态。已注册的 HIVE 和连接应用直接工具仍然可用。HIVE 上下文覆盖层仅暂时隐藏原生来源类型为 `skill-catalog` 的消息。

确实需要详细执行手册时，模型调用无参数的 `hivemind_capabilities` 工具。其持久化工具调用事件就是能力请求。下一次模型步骤中，未修改的原生技能插件会提供当前目录，模型可加载一个相关技能。该机制对未来技能注册保持通用：不包含用户专属值、应用名称分支、提示正则、替代规划器，也不修改原生代理循环。

HIVE Web 配置还把默认 OpenRouter 模型的推理强度设为 Harness 的 `off`，并映射为提供商值 `none`。其他已配置强度仍可通过原生模型配置选择。

## 验证

聚焦的上下文测试证明，问候和模糊的首个步骤不会收到目录，而同一轮次中持久化的 `hivemind_capabilities` 调用会让目录出现。运行时测试证明该工具无需加载档案数据即可注册和执行。预设测试验证首步与简洁澄清契约。Bundle 测试验证 OpenRouter 推理映射和默认强度。

## 考虑过的替代方案

**每轮预加载精简目录。** 拒绝，因为它会给直接回答增加提示成本和规划压力。

**在模型运行前分类请求文本。** 拒绝，因为关键词路由会猜测意图，产生应用专属维护，并可能隐藏模型需要的能力。

**修改原生技能插件或代理循环。** 拒绝，因为 HIVE 是覆盖层，必须不加修改地继承原生 Harness 行为。

**使用 OpenRouter `exclude` 隐藏推理。** 拒绝，因为它只隐藏返回的推理文本，并不会阻止模型消耗推理 token。

## 后果

需要详细技能的任务会增加一次有界的能力请求步骤。直接回答、简洁澄清、单次 HIVE 查询和有界连接应用工作完全避免目录。完整会话事件继续持久化用于重放，而后续普通请求只收到配置范围内的已完成对话投影。
