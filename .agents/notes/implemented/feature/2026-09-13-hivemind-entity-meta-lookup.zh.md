# Agent Note：HIVE 实体查找是渐进式记忆操作

Status: implemented

[English](2026-09-13-hivemind-entity-meta-lookup.md) | 中文

## Problem

不完整的人名或组织名会让记忆召回产生噪声，而在每次召回前强制执行实体发现会增加延迟和不必要的模型步骤。

## Decision

现有 `hivemind_meta` 工具通过 Core `/api/entity-search` 暴露 `entities` 操作。已认证运行时派生租户权限，模型只能提供词法查询、可选实体类型、授权范围收窄和有界结果数量。

对于不完整或有歧义的命名对象，模型执行一次实体查找，并把所选结果的 `canonical_name` 传给 `recall.entities`。名称已经明确或没有命名对象的召回会绕过实体查找。这仍然是原生 Harness 循环内的渐进式工具使用。

## Alternatives considered

**在每次召回前运行实体发现。** 已拒绝，因为对象已经明确或不存在对象时会产生额外成本。

**在代理循环中加入确定性意图路由。** 已拒绝，因为 HIVE 能力继续由模型通过原生工具选择。

**向模型暴露租户或实体数据库标识。** 已拒绝，因为已认证 Core 负责授权和清单范围。

## Consequences

有歧义的名称召回获得基于证据的规范化步骤，且不增加应用专用或用户专用分支。无效范围和限制会在请求 Core 前失败。实体回执在当前轮次中可用，而普通历史投影会从后续模型请求中移除旧工具载荷。
