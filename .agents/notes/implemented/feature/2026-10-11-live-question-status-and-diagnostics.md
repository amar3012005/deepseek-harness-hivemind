# Live parked-question status and receipt-based diagnostics

The native userQuestions projection and closed conversation turn outrank a delayed control-stream running bit for question-wait presentation. A mounted ChatView replaces the activity clock with localized Waiting for your answer. A later open turn remains active even if an older question is unanswered. ContinuedQuestionDock retains original question and authentic late-answer identity; no result, answer or authority is manufactured.

Runtime and persistent employees share a read-only hyperagents_session_diagnostics tool over their own immutable Session.snapshotEvents. It filters actual failed tool/result, turn/end and compaction/end receipts within a bounded UTC window, preserves original sequence and tool identity across surface compaction, paginates, and does not select another room. Native nightly message instructions require this read before deriving failures; private memory supplies work context only. Support email sanitization and correlated reply validation remain authoritative.

Automatic pressure compaction skips a range consisting only of an existing compaction checkpoint. Large static prompt/tool envelopes cannot be reduced by summarizing that checkpoint again. New history remains compactable; explicit manual reduction and provider-confirmed overflow keep their supported behavior. Full saved history and complete tool pairs are retained.

Evidence: focused mounted Runtime/employee UI transitions, late-answer dock, receipt filtering/window/pagination, automatic checkpoint-only regression and native compaction loop checks.
