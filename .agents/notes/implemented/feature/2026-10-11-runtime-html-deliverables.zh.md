# Agent Note: Runtime 的 HTML 交付物

Status: implemented

[English](2026-10-11-runtime-html-deliverables.md) | 中文

## Problem

原有指导建议默认使用 HTML，却允许根据推断的交付需求选择 PDF。通用生成工具描述及员工任务提示没有包含默认格式，因此定时或委派工作可能生成用户未要求的 PDF。

## Decision

Runtime 与 HyperAgent 的永久角色提示、原生生产和设计技能、生成工具描述及员工任务提示，都将保存的 HTML 设为未指定格式的大型书面交付物的默认格式。只有用户明确要求时才生成 PDF 或其他文档格式。已有任务记录的明确最终格式要求仍具权威性；Runtime 在原生 Team 任务描述和验收条件中传递该格式及用户来源。生成继续使用现有 `hivemind_generate` 的 web 提供者。

Runtime 检查完整性结论所需的页面和章节，向员工提供与任务相关的已检查内容或已接受且可读取的原生传递。仅在文字中引用来源不能授权同事读取。在实际检查、验收并完成公司工作后，Runtime 通过现有发送工具向范围内的管理员发送一次完成通知，复用保存的消息键及内容。员工向 Runtime 汇报。

本决策与 [Runtime 阶段指导](2026-10-11-runtime-stage-guidance.zh.md) 一起收紧交付物规则，不替换原生任务所有权、交付物审核、持久化或授权。

## Alternatives considered

保留根据推断选择 PDF 的例外，会继续导致未经用户要求的格式输出。通过宿主分类器改写格式或新增交付物系统，会覆盖已有的用户明确要求或重复原生提供者。在现有角色、任务及生成接口中加入指令，能保留这些要求并复用原生交付机制。

## Consequences

输入内容的格式不会决定输出格式。现有 PDF 来源仍可读取检查。工具参数、生成器可用性及各格式提供者均保持不变。这些是模型指令，不是新的执行循环，也不是根据文字推断用户权限的解析器。Runtime 仍须核实实际输出和通知回执。

## Testing

原生 Persona 和 AgentLoop 测试检查两个已发布预设在人类输入、通话上下文、Schedule 和员工消息输入之后的模型请求。委派测试验证即时和定时提示保留 HTML、PDF 及 PPTX 的明确要求。现有生成测试执行已保存 HTML 提供者和明确格式路径。真实模型行为属于单独的发布验证。
