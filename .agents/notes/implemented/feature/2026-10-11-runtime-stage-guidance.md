# Agent Note: Runtime stage guidance

Status: implemented

English | [中文](2026-10-11-runtime-stage-guidance.zh.md)

## Problem

Runtime receives human requests, schedules, company signals and employee results in one persistent room. Repeated broad wake instructions compete with the current purpose: an ordinary Gmail alert can drift into an old nightly report, and unchanged pending decisions produce repeated invitations. Private semantic recall can also omit newer confirmed direction.

## Decision

The HQ preset holds one permanent Chief of Staff policy. The existing HQ pre-step admission adds short stage guidance from current native source metadata and matched receipts before the first model request. Initial orientation is conditional on current direction; schedules retain their saved purpose; employee results require inspected evidence and the next eligible action; approval and access continuations retain their exact saved scope. Current nightly admission uses the existing authenticated occurrence guard. Historical message wording cannot choose the stage. Administrator-call continuation requires the exact saved call ID and matching authenticated actor; it reconciles only actual speech, preserves interrupted topics and continues already authorized internal work after saving confirmed direction. A call receipt grants no new permission.

The existing Runtime memory request concurrently reads five confirmed agenda heads and eight open uncertainties. Each kind retains its availability separately. A shared 2.5-second deadline and turn cancellation bound admission, including noncooperative reads. Supersession keys, priority and evidence remain bounded. Social turns reuse the existing context-owned predicate and skip operating retrieval. Start Call preserves its prior unavailable-read rejection. Durable events and tool pairs are unchanged.

Native skills remain selective: reuse relevant global/local playbooks, reassess strategy when evidence changes and finish authorized concrete preparation before necessary consequential approval. The preset and rest guidance replace forced repeated invitations. Awakening uses the authenticated dynamic roster without fixed employee assignments or artificial staggered delays. Nightly reporting is ordinary detailed email; it requires neither a business task nor a separate HTML artifact. Saved CRM discovery, private learning and exact blocker correlation remain available in their existing owners. The HQ plugin explicitly injects execution scope for authenticated blocker candidates and resumption. Native owner-uploaded supported documents are read by the existing artifact inspector from their own-room attachment receipts, using the immutable attachment store and existing size/UTF-8/cancellation bounds. A path or filename in prose grants no access; inspected source content or an accepted receipt must be shared before delegation. Capability descriptions expose this narrow reader without adding filesystem access. Urgent authorized work may dispatch during unfinished orientation without inventing a future calendar item; saved future starts and unfinished dependencies still prevent early dispatch.

## Alternatives considered

**Append another universal wake prompt.** Rejected because conflicting older instructions remain active and enlarge every request. The owning preset and rest guidance are replaced instead.

**Classify stages from free-form text.** Rejected because copied reports or employee recommendations cannot establish current lifecycle purpose or human authority. Existing admitted source metadata and receipts provide the boundary.

**Add a coordinator loop or duplicate memory store.** Rejected because native admission, Teams, Schedule, private memory, artifact review and durable waits already provide these operations.

## Consequences

The actual memory-save failure came from a strict optional HQ property read without injection. Memory and the matching workstream approval path now use disposable native optional bindings; Runtime uses the same lifecycle-safe binding. Missing or removed HQ returns to the existing native approval path, and tenant rejection still prevents writes. No new permission is granted. File projection now exposes the full admitted attachment ID alongside its read-only path, so the existing native reader can be selected; a short digest could not address that reader. Delegation requires inspected content or an accepted receipt rather than assuming another room can read the host path.

Native voice finish now separates the saved call receipt from its accepted Inbox handoff. A retry recovers only a missing same-call authenticated follow-up and flushes its native insertion; pending, claimed, admitted or discarded delivery is not replayed. Call provider and actor conflicts reject recovery. The same helper serves live Codex close, while recovering a lost process-local Codex room mapping remains a separate API limitation. A canceled connection request remains closed; it cannot justify a retry or review wake, though independently authorized work can retain its own schedule.

HQ consumes the Runtime-owned call receipt by its exact saved event name and matching identity fields without adding a reverse package dependency. Native regression fixtures use the required actor metadata, branded sender identity, append options and guarded concrete Inbox implementation; full host checks include these fixtures rather than relying on test transpilation alone.

The first request receives purposeful guidance without new event types, routing, stores or model steps. A new operational input admitted during the same turn refreshes only the changed stage directive; company workspace, rest projection and private recall remain once per turn, and unchanged tool steps add no copies. Nightly colleague replies are recognized before their first model request by matching the native sender, original Runtime question, reply receipt and saved nightly occurrence. Recurring batches retain the native first-entry source occurrence while each reminder keeps its own occurrence. Fresh operating heads add bounded concurrent retrieval for substantive HQ turns; failed retrieval remains an explicit gap. Model judgment is still required: helper tests do not prove actual prioritization, delegation or review quality.

The stage fixtures preserve both legacy Team receipt provenance and direct native Inbox sender membership; the separate matched Team compatibility change remains necessary for direct delivery. Persistent employee room messaging keeps its existing receipts. Connector evidence does not become administrator authority. Production rollout and ordinary-model end-to-end proof are independent release responsibilities.

Automatic scheduled recovery concludes at the successful persisted rest receipt through the native tool marker, avoiding a model step solely to repeat unchanged waiting. Human and colleague outcomes remain visible. Empty automatic reviews without task or unresolved calendar work use the four-hour review bound while independently saved timers retain their exact dates. This limits empty review polling without suppressing failures, modifying unrelated schedules or creating another scheduler.
