# Agent Note: Runtime stage guidance

Status: implemented

English | [中文](2026-10-11-runtime-stage-guidance.zh.md)

## Problem

Runtime receives human requests, schedules, company signals and employee results in one persistent room. Repeated broad wake instructions compete with the current purpose: an ordinary Gmail alert can drift into an old nightly report, and unchanged pending decisions produce repeated invitations. Private semantic recall can also omit newer confirmed direction.

## Decision

The HQ preset holds one permanent Chief of Staff policy. The existing HQ pre-step admission adds short stage guidance from current native source metadata and matched receipts before the first model request. Initial orientation is conditional on current direction; schedules retain their saved purpose; employee results require inspected evidence and the next eligible action; approval and access continuations retain their exact saved scope. Current nightly admission uses the existing authenticated occurrence guard. Historical message wording cannot choose the stage.

The existing Runtime memory request concurrently reads five confirmed agenda heads and eight open uncertainties. Each kind retains its availability separately. A shared 2.5-second deadline and turn cancellation bound admission, including noncooperative reads. Supersession keys, priority and evidence remain bounded. Social turns reuse the existing context-owned predicate and skip operating retrieval. Start Call preserves its prior unavailable-read rejection. Durable events and tool pairs are unchanged.

Native skills remain selective: reuse relevant global/local playbooks, reassess strategy when evidence changes and finish authorized concrete preparation before necessary consequential approval. The preset and rest guidance replace forced repeated invitations. Awakening uses the authenticated dynamic roster without fixed employee assignments or artificial staggered delays. Nightly reporting is ordinary detailed email; it requires neither a business task nor a separate HTML artifact. Saved CRM discovery, private learning and exact blocker correlation remain available in their existing owners.

## Alternatives considered

**Append another universal wake prompt.** Rejected because conflicting older instructions remain active and enlarge every request. The owning preset and rest guidance are replaced instead.

**Classify stages from free-form text.** Rejected because copied reports or employee recommendations cannot establish current lifecycle purpose or human authority. Existing admitted source metadata and receipts provide the boundary.

**Add a coordinator loop or duplicate memory store.** Rejected because native admission, Teams, Schedule, private memory, artifact review and durable waits already provide these operations.

## Consequences

The first request receives purposeful guidance without new events, routing, stores or model steps. Fresh operating heads add bounded concurrent retrieval for substantive HQ turns; failed retrieval remains an explicit gap. Model judgment is still required: helper tests do not prove actual prioritization, delegation or review quality.

The stage fixtures preserve both legacy Team receipt provenance and direct native Inbox sender membership; the separate matched Team compatibility change remains necessary for direct delivery. Persistent employee room messaging keeps its existing receipts. Connector evidence does not become administrator authority. Production rollout and ordinary-model end-to-end proof are independent release responsibilities.

## Testing

Focused fixtures cover first-request admission through the actual Loader and native agent loop, social retrieval exclusion, independent agenda supersession, deadline failures, source provenance, historical nightly exclusion, task evidence, approval scope and preserved full history. Host compilation validates package ownership. Controlled fixtures do not establish production email delivery or business reasoning quality.
