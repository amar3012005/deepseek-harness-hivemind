# Agent Note：HIVE-MIND 在完整代理之上组合公司记忆

Status: implemented

[English](2026-09-08-hivemind-company-brain-preset.md) | 中文

## 问题

经过身份验证的公司助手需要组织上下文和记忆，同时不能替换完整 DeepSeek Harness 代理的编码、研究、技能、子代理、工作流、压缩或审批能力。若在每次请求中预先放入完整入职资料或大量组织工具，会增加提示成本，并让模型控制租户权限。

## 决策

`hivemind` 预设镜像完整的 `standard` 代理组合，并增加隔离的 HIVE-MIND 能力组。服务器端身份提供者读取 ICARUS 凭据，推导用户和组织范围，并提供有界的公司简介。一个不含租户参数的 `hivemind_meta` 工具按需加载完整档案、前五条记忆证据或准确的 HyperAgent 档案。其召回 schema 接受来源、项目、时间、标签、媒体类型、文件名和实体过滤器；媒体字段会映射为服务器既有的证据标签。召回的文件名、标题、引用或记忆 ID 始终是内部证据引用，而不是文件系统路径。HIVE 预设保留说明该区别的精简指令，并仅在适用任务中通过原生 Harness 技能加载器加载详细的公司大脑指令。HIVE-MIND 不扫描通用用户或项目技能根目录，因此问候语不会收到庞大的通用技能目录。Web 客户端在 `sidebar.footer.action` 中挂载仅浏览器可见的连接控件；它显示已验证邮箱，但不会接收凭据。

在配置的轮次和字符限制内，已完成的用户请求和最终助手回答会继续保留。推理、工具调用和工具结果保留在仅追加的会话日志中，但不会通过 HIVE-MIND 历史投影进入后续模型请求。当前轮次的回执仍可用于综合回答。

## 验证

运行时测试覆盖所有者控制的凭据、来源和响应限制、无租户参数的 schema、类型化媒体过滤器投影、精简初始上下文、完整上下文加载、带引用的去重召回、HyperAgent 投影以及已完成对话历史。客户端测试覆盖侧栏位置和已验证邮箱显示。预设验证确认发布组合可解析，TypeScript 构建验证主机和客户端能力接线。

## 考虑过的替代方案

**分叉或简化 Harness 循环。** 已拒绝，因为 HIVE-MIND 必须保持完整代理，并继承上游推理和执行改进。

**为每个 HIVE-MIND 端点暴露独立工具。** 已拒绝，因为单个渐进式 schema 可保持常驻提示精简，并防止租户标识成为模型输入。

**在每次请求中注入完整组织档案。** 已拒绝，因为大多数轮次只需要简短简介，而详细任务可以明确请求完整的已验证上下文。

## 后果

在组合继承能力可用之前，HIVE-MIND 预设必须跟踪 standard 预设的新能力。初始提示只携带精简公司简介和一个稳定的元工具 schema。员工执行、连接应用和召回分页继续作为独立的后续能力，而不是隐藏在公司记忆插件中的行为。
