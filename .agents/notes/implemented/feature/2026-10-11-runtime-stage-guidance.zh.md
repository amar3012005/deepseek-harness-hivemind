# Agent Note: Runtime 阶段指导

Status: implemented

[English](2026-10-11-runtime-stage-guidance.md) | 中文

## Problem

Runtime 在同一个持久房间接收用户请求、计划、公司信号和员工结果。重复的通用唤醒指令与当前目的发生冲突：普通 Gmail 提醒可能偏离到旧的每晚报告，未变化的待定决策可能产生重复邀请。私有语义召回也可能遗漏更新的已确认方向。

## Decision

HQ 预设保留一份永久的 Chief of Staff 策略。现有 HQ pre-step 接纳流程根据当前原生来源元数据和匹配回执，在首个模型请求之前加入简短阶段指导。初次了解以当前方向为条件；计划保留已保存的目的；员工结果要求检查证据并推进下一个符合条件的动作；审批与访问恢复保留准确的已保存范围。当前每晚报告接纳采用现有的认证发生记录守卫。历史消息的措辞不能选择当前阶段。

现有 Runtime 记忆请求并发读取五条已确认议程的当前记录与八条未解决的不确定项。每类分别保留可用性。共享的 2.5 秒期限与轮次取消约束接纳耗时，包括不响应取消的读取。版本替代键、优先级与证据保持有界。社交轮次复用 context 包拥有的现有判定并跳过运行记忆读取。Start Call 保留此前读取不可用时拒绝接纳的行为。持久事件与工具调用结果配对不变。

原生技能仍按需使用：复用相关全局或本地执行手册，在证据变化时重新判断策略，并在必要的重要审批前完成获授权的具体准备。预设与休眠指导替换强制重复邀请。初次唤醒使用经过认证的动态成员名单，不固定员工分工或人为错开时间。每晚报告是普通详细邮件，不要求业务任务或单独的 HTML 工件。已保存 CRM 的发现、私有学习与准确的阻塞关联仍由现有能力提供。

## Alternatives considered

**追加另一个通用唤醒提示。** 拒绝，因为旧的冲突指令仍然生效且增加每个请求的长度。因此替换拥有该策略的预设与休眠指导。

**从自由文本分类阶段。** 拒绝，因为复制的报告或员工建议不能确定当前生命周期目的或人类授权。现有接纳来源元数据与回执提供这一边界。

**新增协调循环或重复记忆存储。** 拒绝，因为原生接纳、Teams、Schedule、私有记忆、工件审核与持久等待已提供这些操作。

## Consequences

首个请求获得有目的的指导，不新增事件、路由、存储或模型步骤。新的运行记忆当前记录为实质性 HQ 轮次增加有界并发读取；读取失败仍是明确缺口。模型仍需判断：辅助函数测试不能证明实际优先级、委派或审核质量。

阶段 fixture 保留旧 Team 回执来源以及原生直接 Inbox 发送者成员关系；直接投递仍需要独立匹配的 Team 兼容改动。持久员工房间消息保留现有回执。连接器证据不成为管理员授权。生产发布与真实模型端到端证明是独立的发布职责。

自动定时恢复通过原生工具的结束标记，在休息记录成功持久化后结束当前轮次，避免仅为重复未变化的等待状态而再次调用模型。用户和同事请求仍保留正常可见结果。没有任务或未解决日历事项的自动检查使用四小时检查间隔；独立保存的任务和日历计时器保持原定时间。这不会隐藏失败、修改无关计划或创建另一套调度器。

## Testing

针对性 fixture 覆盖实际 Loader 与原生 agent loop 中首请求的接纳、社交读取排除、独立议程版本替代、期限失败、来源依据、历史每晚报告排除、任务证据、审批范围与完整历史保留。主机编译验证包所有权。受控 fixture 不能证明生产邮件投递或业务推理质量。
