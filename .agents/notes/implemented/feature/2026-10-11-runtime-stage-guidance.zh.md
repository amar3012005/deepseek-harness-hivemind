# Agent Note: Runtime 阶段指导

Status: implemented

[English](2026-10-11-runtime-stage-guidance.md) | 中文

## Problem

Runtime 在同一个持久房间接收用户请求、计划、公司信号和员工结果。重复的通用唤醒指令与当前目的发生冲突：普通 Gmail 提醒可能偏离到旧的每晚报告，未变化的待定决策可能产生重复邀请。私有语义召回也可能遗漏更新的已确认方向。

## Decision

HQ 预设保留一份永久的 Chief of Staff 策略。现有 HQ pre-step 接纳流程根据当前原生来源元数据和匹配回执，在首个模型请求之前加入简短阶段指导。初次了解以当前方向为条件；计划保留已保存的目的；员工结果要求检查证据并推进下一个符合条件的动作；审批与访问恢复保留准确的已保存范围。当前每晚报告接纳采用现有的认证发生记录守卫。历史消息的措辞不能选择当前阶段。管理员通话恢复要求准确的已保存通话 ID 和匹配的认证参与者；只核对实际发言，保留中断的话题，并在保存已确认方向后继续已有授权的内部工作。通话回执不授予新权限。

现有 Runtime 记忆请求并发读取五条已确认议程的当前记录与八条未解决的不确定项。每类分别保留可用性。共享的 2.5 秒期限与轮次取消约束接纳耗时，包括不响应取消的读取。版本替代键、优先级与证据保持有界。社交轮次复用 context 包拥有的现有判定并跳过运行记忆读取。Start Call 保留此前读取不可用时拒绝接纳的行为。持久事件与工具调用结果配对不变。

原生技能仍按需使用：复用相关全局或本地执行手册，在证据变化时重新判断策略，并在必要的重要审批前完成获授权的具体准备。预设与休眠指导替换强制重复邀请。初次唤醒使用经过认证的动态成员名单，不固定员工分工或人为错开时间。每晚报告是普通详细邮件，不要求业务任务或单独的 HTML 工件。已保存 CRM 的发现、私有学习与准确的阻塞关联仍由现有能力提供。HQ 插件明确注入执行范围，用于认证阻塞回答候选和恢复。现有工件检查器根据本房间附件回执读取原生用户上传的受支持文档，复用不可变附件存储及现有大小、UTF-8 和取消限制。正文中的路径或文件名不授予访问权限；委派前必须共享已检查的来源内容或已接收的回执。能力描述公开这一受限读取能力，不新增文件系统权限。已有授权的紧急工作可在初始了解尚未结束时立即分派，无需虚构未来日历项；已保存的未来开始时间与未完成依赖仍阻止提前分派。

## Alternatives considered

**追加另一个通用唤醒提示。** 拒绝，因为旧的冲突指令仍然生效且增加每个请求的长度。因此替换拥有该策略的预设与休眠指导。

**从自由文本分类阶段。** 拒绝，因为复制的报告或员工建议不能确定当前生命周期目的或人类授权。现有接纳来源元数据与回执提供这一边界。

**新增协调循环或重复记忆存储。** 拒绝，因为原生接纳、Teams、Schedule、私有记忆、工件审核与持久等待已提供这些操作。

## Consequences

实际记忆保存失败源于未注入 HQ 时读取严格可选属性。记忆和相同的工作流审批路径现在使用可释放的原生可选绑定；Runtime 使用相同的生命周期安全绑定。HQ 缺失或移除时恢复现有原生审批路径，租户拒绝仍阻止写入，不授予新权限。文件投影现在在只读路径旁展示完整的已接纳附件 ID，使现有原生读取器能被选用；短摘要无法定位该读取器。委派必须共享已检查内容或已接收回执，不能假定另一房间能读取主机路径。

原生通话结束现在区分已保存通话回执和已接纳 Inbox 交接。重试只恢复缺失的同一通话认证后续输入，并持久化原生插入；待处理、已认领、已接纳或已丢弃投递不重放。通话提供方或参与者冲突拒绝恢复。相同辅助函数服务于实时 Codex 通话关闭；进程重启后丢失 Codex 房间映射的恢复仍是独立 API 限制。取消的连接请求保持关闭，不能产生重试或检查唤醒；独立获授权的工作可保留自己的计划。

HQ 根据准确的已保存事件名称和匹配身份字段读取 Runtime 拥有的通话回执，不新增反向包依赖。原生回归 fixture 使用必需的参与者元数据、品牌化发送者身份、追加选项和经过类型守卫的具体 Inbox 实现；完整主机检查包含这些 fixture，不只依赖测试转译。

首个请求获得有目的的指导，不新增事件类型、路由、存储或模型步骤。同一轮次中接纳新的运行输入时，只刷新发生变化的阶段指令；公司工作区、休眠投影与私有召回仍每轮读取一次，未变化的工具步骤不添加副本。每晚报告的同事回复通过匹配原生发送者、Runtime 原始问题、回复回执及已保存的每晚发生记录，在首个模型请求之前识别。循环提醒批次保留原生第一条目的来源发生时间，每条提醒仍保留自身的发生时间。新的运行记忆当前记录为实质性 HQ 轮次增加有界并发读取；读取失败仍是明确缺口。模型仍需判断：辅助函数测试不能证明实际优先级、委派或审核质量。

阶段 fixture 保留旧 Team 回执来源以及原生直接 Inbox 发送者成员关系；直接投递仍需要独立匹配的 Team 兼容改动。持久员工房间消息保留现有回执。连接器证据不成为管理员授权。生产发布与真实模型端到端证明是独立的发布职责。

自动定时恢复通过原生工具的结束标记，在休息记录成功持久化后结束当前轮次，避免仅为重复未变化的等待状态而再次调用模型。用户和同事请求仍保留正常可见结果。没有任务或未解决日历事项的自动检查使用四小时检查间隔；独立保存的任务和日历计时器保持原定时间。这不会隐藏失败、修改无关计划或创建另一套调度器。

## Testing

针对性 fixture 覆盖实际 Loader 与原生 agent loop 中首请求接纳和同一轮次的阶段刷新、匹配的管理员通话、不可变上传文件读取、经过认证的阻塞执行、立即分派就绪工作以及未来时间/依赖/Pause 拒绝、每晚回复首请求与混合循环批次、社交读取排除、独立议程版本替代、期限失败、来源依据、历史每晚报告排除、任务证据、审批范围与完整历史保留。主机编译验证包所有权。受控 fixture 不能证明生产邮件投递或业务推理质量。
