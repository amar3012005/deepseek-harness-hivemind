# Agent Note: 租户媒体所有权与持久准入

Status: implemented

[English](2026-10-02-tenant-media-admission.md) | 中文

## 决策

生产媒体预设要求服务端提供组织、用户和会话所有权。返回身份坐标前检查带作用域的会话持久存储。提供方操作状态及产物凭据绑定该所有者。各会话挂载共享一个运行器队列，设置全局和组织并发限制，并使用 SQLite 持久记录每日预留配额。

## 恢复与替代方案

派发前将已接受请求保存到会话。授权会话重新打开时恢复尚未派发的请求；已提交的 Codex 请求只核对已有结果，不重新生成，并复用原工作流标识。提交前同步保存私有提供方意图。结果未知的视频提交需要提供方核对，不得盲目重试。生产目前只有一个运行器，因此暂不引入分布式队列；多个副本必须替换进程内调度器。尚未实现关闭会话的自动恢复。

## 影响与验证

生产默认全局四个任务、每组织一个、最多一百个排队请求，每用户及组织每天 UTC 最多五十个不同的已准入操作。失败的已准入请求也占用预留配额。取消移除排队工作；关闭时中止工作进程，等待活动槽位释放后再关闭数据库。针对性测试覆盖所有权不匹配、持久配额、租户并发、重复准入、取消、完成产物所有权和未知结果不重新生成。提供方故障与账户限制仍可能发生；这些修改不承诺零失败，也不为每租户提供独立提供方账户。
