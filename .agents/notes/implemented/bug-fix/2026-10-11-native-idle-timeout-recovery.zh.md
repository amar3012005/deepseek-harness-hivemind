# Agent Note: 原生空闲超时恢复

Status: implemented

[English](2026-10-11-native-idle-timeout-recovery.md) | 中文

## 问题

仅中止信号的空闲监视器无法结束不配合的提供方读取。等待异步生成器清理会把新的等待排在该读取之后，使原生循环无法收到超时，也无法恢复已保存的工作。

## 决策

现有超时工具采用官方 `dsh-v0.2.1-alpha.2` 的需求结算行为：自身空闲截止时间独立于提供方配合，拒绝尚未完成的读取需求。稳定信号仍负责通知资源终止。pi-ai 适配器发起生成器清理但不等待已放弃的读取，并将监视器拒绝携带的确切原因转换为原生 `TIMEOUT`；显式调用方取消保持 `ABORTED`。现有提供方重试策略和 Session 历史负责继续执行，没有新增调度器、恢复队列或消息重放。

## 考虑过的替代方案

**等待提供方清理。** 不配合的读取可能使调用方永久收不到截止时间，因此拒绝。

**重放发起消息或已完成的工具。** 原生 Session 结果保留已完成的输出并负责恢复，因此拒绝。

## 影响

结算放弃的需求不代表外部提供方已经停止工作。能力所有者仍负责传输取消与清理。消费方处理时间不计入空闲时间，活动脉冲重新启动挂起读取的计时，总截止时间保持独立。生产中已确认停滞工作的受管重启需要保留前后记录并使用原生恢复；源码测试不证明线上恢复成功。

## 测试

不配合的 SDK 迭代器在修复前复现无界等待，修复后收到原生 `TIMEOUT`。超时工具和 pi-ai 适配器测试覆盖截止时间、活动脉冲、调用方取消、凭据错误与普通流式传输。DeepSeek 适配器测试验证另一处空闲监视器消费者。
