# Agent Note: Runtime team message summaries

Status: implemented

[English](2026-10-10-runtime-team-message-summary.md) | 中文

## Problem

员工任务和夜间检查结果的完整内容显示在聊天气泡中，即使指令要求简短更新。缩短底层消息会丢失员工执行任务和 Runtime 审核需要的上下文。

## Decision

现有持久房间消息支持可选的 `summary`：最多 240 个字符的一行非空文字。发送方同时提供简短显示内容和完整 `text`。发件记录、接收房间及模型消息保留两者。复用消息键时，摘要和完整正文必须一致。

聊天气泡优先显示有效摘要，然后使用现有经过验证的任务投影或简短原文。没有摘要的历史长消息显示中性更新提示，不推断成功结果。完整原始消息仍可在默认收起的 Agent message 详情中查看，包括公司聊天。附件按钮继续使用现有的准确保存凭据。

Runtime 和 HyperAgent 的角色指令区分简短阶段更新与完整底层消息。Runtime 在现有权限内解决常规疑问，协调主动工作的专家。类型化任务阻塞可直接提供通知引用，无需额外创建阻塞提问。原生审批、下游拒绝、租户、提供商及当前任务修订审核边界保持不变。Full access 说明仅限明确豁免；原生 never 策略拒绝其他审批请求。

## Alternatives considered

**缩短保存的消息。** 这会丢失员工执行任务和夜间报告需要的指令及技术证据。

**从详细正文推断摘要。** 这可能制造不存在的结果。历史消息使用中性提示，当前发送方明确提供受支持的摘要。

**修改审批服务。** 问题在于指令和显示方式。权限继续由现有原生服务管理。

## Consequences

详细沟通保持持久且可检查，同时减少聊天中显示的长内容。可选摘要兼容旧会话，仅描述消息，不授予权限。发布后仍需真实模型验证发送行为。
