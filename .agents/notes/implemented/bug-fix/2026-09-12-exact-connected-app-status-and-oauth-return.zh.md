# Agent Note: 精确的连接应用状态与 OAuth 返回

状态：已实现

[English](2026-09-12-exact-connected-app-status-and-oauth-return.md) | 中文

## 问题

纯连接状态请求曾被送入语义工具搜索。搜索适用于真实应用任务，但它可能选中另一个能够完成所描述操作的工具包。因此，明确的 Instagram 状态检查可能错误地要求连接 ScrapeCreators。即使提供商已经成功重定向，授权流程仍要求用户手动返回并点击继续。

## 决策

HIVE 连接应用桥现在提供与具体应用无关的 `connection_status` 动作。它使用已认证 Composio 会话的工具包元数据解析用户明确命名的应用，并且只接受规范化 slug 或名称唯一精确匹配。真实应用工作仍使用完整的 `COMPOSIO_SEARCH_TOOLS` 发现流程；没有增加任何提供商或应用专用路由规则。原生连接卡作为持久的内联会话事件保留。授权验证成功后，已完成的工具结果会在同一会话中呈现更紧凑的已连接回执；真实应用工作流随后从保存的 Composio 计划继续。纯状态检查从该回执直接结束，不再增加模型步骤。

Composio 会话按 HIVE 对话隔离，同时仍以稳定的已认证用户作为连接所有者。配置回调后，授权会返回该对话的规范会话 URL。回调标签页通过 `BroadcastChannel` 通知原标签页；原先暂停的原生问题随后验证连接并继续同一个工具调用。手动继续仍作为后备。该设计不依赖本地存储，并保留 Harness 原生的问题、收据和回放生命周期。

原生连接卡片使用更小的工具包图标。对于明显的直接回答或单工具分发，HIVE persona 不再叙述推理；只有确实需要时才显示推理，并限制为最多四个短句。

## 后果

纯命名应用状态检查变得更便宜且精确，而真实应用工作仍保留 Composio 的语义发现质量。OAuth 成功返回后可以自动恢复已暂停的原生交互。回调需要配置公开的 HIVE 基础 URL，并依赖浏览器支持 `BroadcastChannel`；现有手动继续操作仍作为兼容性后备。

## 曾考虑的替代方案

- 增加 Instagram 专用路由规则：否决，因为未来每个应用都会需要新的例外，而已认证工具包目录才是权威来源。
- 对状态检查继续使用语义搜索：否决，因为操作相关性不等于应用身份。
- 在原 HTTP 请求中无限轮询或将回调状态存入本地存储：否决，因为 Web 请求应保持有界，且嵌入式存储可能不可用。

## 验证

聚焦的连接应用、回调、连接问题、浏览器插件和已发布 preset 测试覆盖：精确工具包选择、状态检查不使用语义搜索、回调构造与传递、原生继续，以及既有搜索和恢复行为。
