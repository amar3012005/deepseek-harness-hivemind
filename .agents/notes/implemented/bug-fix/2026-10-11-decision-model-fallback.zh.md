# Agent Note: 决策模型回退

Status: implemented

[English](2026-10-11-decision-model-fallback.md) | 中文

## 问题

Mercury 的临时故障会使授权活动保持待处理。当前 OpenRouter 凭据也以 HTTP 402 拒绝 Mercury 和 Jev；仅更换模型不能恢复该账户的容量。

## 决策

现有专用 Decisions 提供程序接受固定版本的 Mercury、免费 Mercury 和 Jev 模型。主模型传输或输出失败后，服务器配置的备用模型接收相同的类型化状态和问题。Web 配置选择 Jev 作为 Mercury 的备用，并在八秒总期限内允许主推理运行六秒。此前 1.2 秒主期限和三秒总期限在已验证的免费网关路由实时恢复中超时。成功响应立即返回；期限是最大值，不是强制等待。调用方取消会停止恢复。消费前，每个响应都必须通过原有的键控原语和归一化分布验证。每次尝试都解析凭据；不记录正文和密钥。

## 考虑过的替代方案

**推理失败时强制通知。** 否决，因为提供程序故障不能确定信号的价值或紧急程度。现有待处理账本保留恢复能力，而不伪造决策。

**使用同一个余额不足凭据切换模型。** 不足以解决问题，因为两个实际探测都返回 HTTP 402。部署仍需要可用的凭据路由和实时验证。

**添加另一个事件接收器。** 否决，因为现有事件标识、分类重试和原生投递已保持去重。

## 后果

每次评估最多进行两次模型尝试，并产生一个经验证的决策。有效的主响应不会调用备用模型。共享账户计费或网关认证故障仍可能使两次尝试均失败；事件会保持待处理直到容量恢复。不改变会话、权限或投递契约。
