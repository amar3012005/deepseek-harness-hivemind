# Agent Note: Runtime 的明确范围与有界发现

Status: implemented

[English](2026-10-13-runtime-clear-scope-and-bounded-discovery.md) | 中文

## Problem

Runtime 可能因重复发现和提问而推迟明确的团队请求。合约列表返回历史回执集合并执行协调更新，因此不能安全地把整个操作标记为可并发。

## Decision

Runtime 和 HyperAgent 指令将明确指定的受众视为已授权名册内的请求范围，自行处理常规可逆选择，仅在缺失证据、权限或重要决策改变下一步行动时提问。独立且支持并发的只读调用可放在同一原生工具批次中；有依赖的读取、写入和共享浏览器操作保持顺序执行。

普通 HQ 合约列表仅读取已保存的当前记录，不创建员工房间、不协调工件回执，也不轮询派发状态。部署配置的条目和 UTF-8 字节预算限制完整响应。精确任务查询及绑定版本的分页保留对已保存工作的访问。检查和显式派发刷新保留串行协调。原生任务、验收、历史、界面和授权仍由现有组件负责。

## Alternatives considered

- 仅提示并行读取仍会让带更新的列表路径不安全。
- 将全部合约操作标记为可并发会允许冲突的派发与审核写入。
- 新规划器、任务数据库或派发器会重复原生职责，且无法解决发现开销。
- 完全取消问题会阻止必要的人类决策和真实批准。

## Consequences

发现返回简短当前记录、数量与引用；工件检查提供完整证据。名册或看板变化要求重新读取第一页，普通工具结果不会使分页失效。单条记录无法满足完整字节预算时明确失败。真实 Loader/AgentLoop 夹具验证首次请求指令、重叠读取及持久结果。夹具证明组合和并发，不证明生产中普通模型完成工作。
