# Agent Note: HIVE Chat progressive kernel

Status: proposed

## Problem

HIVE Chat 在尚未知道用户需要公司检索、工件、连接应用工作或简单回答前，就发送宽泛策略提示、长回放窗口和常规过程披露。这会增加模型输入，并把实现活动呈现为对话。

## Proposal

HIVE Chat 预设保留现有的租户范围身份、记忆、连接应用、工件渲染、会话和审批服务。模型可见人格改为精简公司大脑内核。详细的记忆治理、公司研究和工件交付指令成为按需技能，通过现有文件系统提供者发现，并仅在匹配请求时由现有技能工具加载。连接应用工作流指导继续保留在现有按需技能中。

工作回放限制为三轮和 3,000 个字符。HIVE Chat UI 隐藏通用回合过程控件；待处理工作仍由产品活动指示器表示，而持久会话记录保留诊断信息。

## Alternatives considered

**用迁移分支替换 HIVE runner。** 拒绝，因为这需要重新验证 HIVE 渲染、连接应用、租户隔离和持久化，同时仍保留较大的基础人格和未解决的 toolkit 挂载依赖。

**从预设中移除 HIVE 服务。** 拒绝，因为常驻服务能保留已认证能力，而不必在每个模型请求中带入详细指令。

**修改原生 agent loop。** 拒绝，因为预设、技能发现和聊天渲染器都是现有原生扩展点，不需要修改 loop。

## Acceptance criteria

- 新 HIVE Chat 请求具有精简人格、三轮回放且没有常规进度指令。
- 公司检索、记忆变更、研究、连接应用工作和工件工作仅在调用时加载详细指令。
- HIVE Chat 路由没有通用 Work details 或 Thinking 控件。
- 租户范围服务、原生审批、工件交付和连接应用行为仍可用。
- 发布前，已登录 canary 记录提供方输入 token、首个回答文本、工具时间、最终完成和回滚证据。

## Risks

精简内核可能遗漏专用安全或工作流规则，如果匹配技能没有加载。发布因此需要覆盖记忆写入、连接应用写入、外部研究和工件交付。现有客户端记录首个 token 和最终完成；完整请求大小和首个回答跟踪仍是独立的遥测补充。
