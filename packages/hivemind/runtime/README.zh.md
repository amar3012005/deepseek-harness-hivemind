# @deepseek-ai/dsh-hivemind-runtime

[English](README.md) | 中文

## 摘要

`dsh-hivemind-runtime` 将 Harness 代理绑定到 ICARUS 保存的 HIVE-MIND 身份。它验证本地凭据并在服务器端解析用户和组织范围。首轮会加入有界、带版本的认证档案摘要；后续仅在直接询问用户或公司档案时刷新该摘要。HIVE 模式暴露有界的直接工具和一个按需能力目录工具，保留最近完成的用户请求和最终回答，并从后续模型请求中移除旧工具载荷。凭据和租户标识不会进入模型可见的 schema 或结果。

## 使用此包

在提供 `tools` 和 `skills` 的代理预设中挂载此插件：

```yaml
- insert:
    - id: hivemind-runtime
      name: '@deepseek-ai/dsh-hivemind-runtime'
      config:
        agentFeaturesEnabled: true
        legacyToolsEnabled: false
        icarusConfigPath: '~/.icarus/config.json'
        requestTimeoutMs: 20000
        responseMaxBytes: 2097152
        profileContextMaxChars: 12000
        profileBriefMaxChars: 1200
        recallResultLimit: 5
        recallItemMaxChars: 16000
        historyTurns: 5
        historyMaxChars: 8000
```

ICARUS 凭据必须是当前用户拥有且组或其他用户不可写的普通文件。运行时仅接受 `https://core.singulancelabs.com` 或 loopback API 来源，拒绝重定向，限制响应体，并应用明确的请求超时。

## 语义

运行时组合三个可独立测试的能力：`hivemind-context` 负责等待式提示投影，`hivemind-memory` 负责模型可见工具，`hivemind-employee-directory` 验证准确的组织 HyperAgent 档案。第一步模型请求获得系统契约、有界认证档案摘要、有界的已完成对话，以及当前未完成工作流状态。后续直接询问用户或公司档案时会重新加载摘要，因此服务器端版本变化会在下一次相关轮次出现。已注册的直接工具仍然可用，但原生技能目录暂不提供。需要详细执行手册时，模型调用 `hivemind_capabilities`；下一次原生 Harness 步骤会获得当前目录，模型再加载一个相关技能。该流程不修改原生规划器、工具注册表或代理循环。历史投影在 `historyMaxChars` 内最多保留 `historyTurns` 个完成的用户请求和最终助手回答；推理、工具调用和工具输出保留在仅追加日志中，但不会进入后续模型请求。

`hivemind_meta` 支持 `context`、`entities`、`recall`、`save`、`save_status` 和 `profiles`。召回暴露一个去重后的有界结果列表，保留重要内容和引用元数据，并将每条证据限制在 `recallItemMaxChars` 内。实体结果在上游提供时包含规范名称、别名、类型和关联记忆数量。预期的可选服务故障会返回 `entity_index_unavailable`、`memory_retrieval_timeout`、`profile_context_unavailable` 或 `feature_unavailable`，而不会把不可用读取伪装成权威空结果。任何操作都不接受用户或组织标识。

## 开发说明

源包负责身份支持的组合和本地连接路由。不要把凭据和租户权限放入浏览器代码、工具参数或模型可见结果。

## 原生网络搜索

`nativeWebSearch` 默认为 `false`；HIVE Chat 和 HyperAgents 预设保留现有搜索能力。启用后，认证搜索工具先调用选定的 `ctx.web` 提供方；凭据缺失、提供方失败、来源为空或主要期限到达时，回退到现有租户网络任务服务。用户取消会停止两个路径。原生 OpenAI 提供方见 [web-search-openai](../../web/web-search-openai/README.zh.md)。两个路径都遵守现有 HIVE 身份和审批规则。

## 模型体验

### 渐进式 HIVE 能力访问

#### 模型看到的内容

模型最初会看到系统契约、有界认证档案摘要、最近完成的对话、未完成工作流状态和网关工具，但看不到技能目录。它可以直接从摘要回答用户或公司档案问题，仅在摘要不足时调用 `hivemind_meta context`，也可以调用其他有界工具或通过 `hivemind_capabilities` 请求精简目录。当前轮次的工具结果可用于综合，并由历史投影从后续轮次中移除。

#### Token 影响

初始请求承担有界档案摘要和直接工具 schema 的成本，但不包含技能目录、完整组织档案或旧工具回执。后续普通轮次不带摘要；后续直接档案问题会刷新摘要。详细执行手册仅在当前轮次增加一次能力请求回执和一次原生目录。

#### KV Cache 影响

稳定的系统契约和已注册工具列表可以复用。档案证据、目录内容和任务回执只在请求时出现在该前缀之后。

## 已知限制和延后工作

- 该集成为只读能力：员工执行和连接应用操作仍是独立能力。
- 浏览器身份验证使用本地 ICARUS 配置，而不是托管式多租户凭据服务。
- 超出首批前五条结果的渐进式召回分页尚未实现。

## 持久 HyperAgents 会话归属和任务记忆

启用 `privateMemoryEnabled` 后，首个获准轮次将选定的目录员工或 Team Lead `lead` 写入 `hivemind/session-owner`，之后锁定原生员工选择。每轮使用相同的归属指令；专门技能不改变员工身份。

完成的用户和计划响应产生持久的 `hivemind/task-memory-pending` 发件箱记录。签名传输将请求、已交付回答、作者、时间、会话及轮次引用、有界工具回执写入私有 `task_status/completed` 记忆。这里的完成表示响应已交付，外部操作仍须成功工具回执。成功记录追加 `hivemind/task-memory-recorded`；确定性键防止重试和恢复重复，失败写入保留在队列中，在活动期间或认证恢复时重试。手动记忆保存不能改变作者或写入运行状态。召回可筛选认证组织内的员工，公司 HIVEMIND 记忆保持独立。

`src/continuity.ts` 构建响应回执和发件箱投影；`src/index.ts` 负责 Cordis 生命周期、认证发送和重试。原生员工选择器投影持久归属事件；Swarm 模式仍是未来功能。`hyperagentOwner` 会话投影使归属在原始事件超出客户端历史分页窗口后仍可用。

## 完整成果生成

实质性的书面成果默认通过 `hivemind_generate` 的 `format: web` 保存为 HTML。PDF 和其他文档格式需要明确的人类格式要求；已保存的明确任务要求仍有效。Runtime 在原生 Team 任务描述和验收条件中携带格式及其人类来源。读取 PDF 来源不代表选择 PDF 输出。员工向 Runtime 报告保存的成果；实际检查、接受和完成后，Runtime 使用现有有范围、幂等的发送器发送一次管理员完成通知。

原生 `hivemind-artifact-production` 技能为 Runtime 和员工提供按需品牌上下文、完整格式规划、能力发现和实际输出检查指导。目录共享摘要，完整内容仅在制作或可执行制作阻塞时加载。成果回执不代表任务完成，也不会隐藏后续制作工具；租用能力和执行授权仍是权威。当前演示文稿生成支持文字幻灯片，不支持图像组合；Markdown PDF 渲染忽略图像引用。不支持的组装应明确报告为能力缺口。

## 公司策略指导

共享原生 `hivemind-company-strategy` 技能为普通战略议题和员工贡献提供按需方法，并非仅用于觉醒。两个预设都提供策略和完整成果生成的精简路由提示。永久身份及审批规则留在预设中，完整方法通过现有技能注册表加载。Runtime 在保存的任务描述中传递相关策略、品牌和方法引用，员工在权限内解决实质缺口。动态员工响应指导将详细受派工作保留在成果中，向 Runtime 返回精简结果，不主动提出导出；直接用户请求保留要求的形式。召回预算和历史投影不变。

自动终止员工报告仅适用于持久 Chief 指派或认证收到的 Chief 问题。直接员工对话及失败轮次保留在员工房间中；员工通过现有消息工具决定是否向 Runtime 提交实质公司更新或访问问题。模型无法报告时，受派失败仍产生通用终止阻塞通知；确认的明确回复抑制重复自动通知。该规则依赖消息来源，而非内容分类器。

## Runtime 决策记忆和通话

仅认证根 HQ 房间获得有范围的 `runtime_user_agenda` 和 `runtime_uncertainties` 工具，二者包装现有私有运营记忆。Core 验证签名操作者和持久房间归属，按组织及用户隔离记录，并从普通召回中排除这些种类。议题需要保存的直接用户消息或实际用户讲话的通话；来源支持归因，不会自动验证所有声明。私有保存及召回无需审批。证据和影响可选且有界。议题来源默认使用最近保存的直接用户消息或实际讲话通话。不确定性保存优先级及未解决、已解决状态，更新使用不可变后继和精确回执，创建时间保留日期版本。无查询召回返回当前记录，开放疑问按优先级及新近程度排序；模型仍须判断与当前工作的相关性。

Start Call 在接纳任一语音提供方前等待新鲜的不确定性和确认议题读取；读取失败会拒绝接纳，不会伪装成没有待决事项。员工通话不变。保存的 Runtime 通话排队一次原生后续轮次以核对确认回答，未回答或中断主题保持开放。确认不会扩展外部动作权限或发布公司记忆。先部署 Core 种类约束迁移和 API，再部署运行器；不会自动迁移现有生产记录。

Runtime 初次语音基线结果可省略技术通话 ID。工具选择最近保存的同房间初次检查；后续通话不能替代初次证据，完成仍需用户讲话、非空转录和未中断通话。明确错误 ID 被拒绝并提供修复提示。

## 原生夜间审查

现有 `Nightly report` Schedule 无需打开浏览器即可交付到租户保存的 Runtime 房间。获准的原始发生记录加入精简提醒，原生 `skill` 工具按需加载 `hivemind-nightly-routine-check`。目录只携带元数据；详细指令不会复制到每步，也不由独立调度器或任务循环替代。

Runtime 向获准活动员工保存详细 `hivemind_agent_message` 问题，聊天叙述保持简短。员工检查自身授权日常工作和回执，返回与原始请求及发生记录关联的详细回复。Runtime 加入自身证据，审查当前成果修订，将缺失回复或不可用证据记录为覆盖缺口，渐进加载上下文并保存、检查完整组织授权 HTML 成果。该审查不授权修复或公司记忆写入。

`runtime_support_report` 保留现有验证技术邮件路径：Core 渲染转义且组织感知的 HTML，选择配置的平台管理员支持邮箱，按租户、房间、原始发生记录去重。接受不等于交付，须检查实际交付账本；未知结果或变化的载荷需核对，不能创建新邮件身份重发。

先部署现有 Core 详细报告后端及有范围配置，再部署匹配运行器。集成后，操作员的 `--apply --upgrade` 使用原生比较更新修改现有标题、指令，保留时间、时区和身份；指令升级不能恢复非活动记录。初次创建默认权威组织时区午夜，未设置时区则使用 UTC。应用前检查保存记录。

实际验收须保留单一计划身份及时间，证明冷计划接纳和原生技能加载回执，将员工请求与保存的详细回复匹配，检查报告及当前修订审查。核对可见摘要与真实调用，诚实报告不可用覆盖，确认认证组织称呼及配置收件人，分别检查提供方接受和交付。同一报告重复执行不能再发邮件。限制角色和跨租户验证仍必要；真实邮件验证由协调者执行，不是构建测试。

### Runtime 权限请求通知

Runtime 的管理员消息工具及 HQ 政策要求为真正保存的审批或应用连接请求立即发邮件，解释原因。Core 绑定收件人、组织及安全认证房间、动作链接。复用保存的请求身份，连接产生者的现有尝试不能造成第二封邮件。打开链接不授予权限；恢复前需验证输入。未知交付核对而非改身份重发。这不替代原生审批产生流程；模型等待时无法执行其他工具的原生阻塞审批需要产生者通知钩子。

原生停驻权限审批也在现有等待式 `agent/turn-stopping` 接缝通知。仅持久 Runtime 且当前轮次 `tool/call`、`approval/asked` 和待决 `approval/decided` 匹配时符合条件。日志先刷新，再使用 `<callId>-user-request` 调用有范围的管理员发送器。Core 负责认证收件人、偏好、交付回执和持久幂等；恢复发生记录在同一键下核对相同内容。通知传输有十秒取消期限。失败或禁用邮件不批准工作，也不阻止停驻轮次结束；不改变非停驻交互审批行为。
